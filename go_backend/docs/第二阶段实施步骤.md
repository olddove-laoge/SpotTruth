# SpotTruth Go 网关第二阶段实施步骤（D4-D7）

更新时间：2026-04-02
目标范围：P0-3（JWT 鉴权接入主链路 + 公共路由白名单 + 统一鉴权错误语义）

## 一、步骤进程

1. 步骤 1：设计鉴权接入点与白名单（先完成）
   - 入口层：在网关 handler 内统一鉴权，不改下游 Flask 业务逻辑。
   - 白名单：`/healthz`、`/api/v1/auth/login`、`/api/v1/auth/refresh`。
   - 角色路由：`/api/v1/admin/*` 仅 admin/system；`/api/v1/internal/*` 仅 system。

2. 步骤 2：配置化接入（再完成）
   - 新增配置：`AUTH_ENABLED`、`AUTH_SIGNING_KEY`、`AUTH_ISSUER`、`AUTH_ACCESS_TTL`。
   - 启动时按配置构造 TokenManager，并决定启用无鉴权或鉴权 handler。

3. 步骤 3：统一错误语义（再完成）
   - 统一复用 `internal/auth/middleware.go` 的 JSON 错误结构：
     - 缺失/非法 token -> 401
     - 角色不足 -> 403

4. 步骤 4：自动化测试（再完成）
   - 覆盖三类验收场景：
     - 鉴权通过（200）
     - 鉴权失败（401）
     - 越权访问（403）
   - 补充白名单绕过鉴权测试。

5. 步骤 5：联调验证与结果归档（最后完成）
   - 执行 `go test ./...`、`go build ./...`、`go vet ./...`。
   - 给出本地联调预期与实际观测结果。

## 二、验收标准

1. 未携带 token 访问受保护路由返回 401。
2. user token 访问 admin 路由返回 403。
3. user token 访问普通受保护路由可透传上游。
4. 白名单路由不需要 token。
5. 自动化测试覆盖通过/失败/越权三类场景并全部通过。

## 三、实施结果（2026-04-02）

1. 已完成 JWT 鉴权接入主链路：
   - 启用 `NewHandlerWithAuth` 处理受保护路由。
   - 白名单路由可直接透传，不要求 token。

2. 已完成统一鉴权失败结构：
   - 缺失 token 返回 401，错误码 `AUTH_TOKEN_MISSING`。
   - 非法/过期 token 返回 401，错误码 `AUTH_TOKEN_INVALID`。
   - 角色不足返回 403，错误码 `AUTH_PERMISSION_DENIED`。

3. 已完成自动化测试覆盖：
   - 鉴权通过（200/透传）
   - 鉴权失败（401）
   - 越权访问（403）
   - 白名单绕过鉴权

4. 验证命令与结果：
   - `go test ./...`：通过
   - `go build ./...`：通过
   - `go vet ./...`：通过
