# 第四阶段回归清单（熔断与降级）

更新时间：2026-04-09

## 一、执行前检查

1. Go 网关已启动，读取到 `CB_ENABLED=true`。
2. 上游 Flask 服务可控（可正常运行，也可手动停止用于故障注入）。
3. 已确认网关地址（默认 `http://127.0.0.1:8080`）。

## 二、正常链路回归

1. `curl -sS http://127.0.0.1:8080/healthz` 返回 200。
2. `curl -sS http://127.0.0.1:8080/readyz` 在上游正常时返回 200。
3. 业务路由请求在上游正常时返回非降级结果（非 `GATEWAY_DEGRADED`）。

## 三、故障注入回归

1. 停止上游 Flask（或让网关上游指向不可用地址）。
2. 执行：

```bash
cd go_backend
bash scripts/fault_injection_circuit_breaker.sh http://127.0.0.1:8080 /api/v1/search 8
```

3. 预期结果：
   - 初期请求可能出现 5xx（下游失败透传阶段）。
   - 随后出现 `503 + GATEWAY_DEGRADED`。
   - `degrade_reason` 出现 `open_circuit`。

## 四、恢复链路回归

1. 恢复上游 Flask。
2. 等待 `CB_TIMEOUT` 之后重试业务请求。
3. 预期结果：
   - 熔断进入 half-open 探测并逐步恢复闭合。
   - 请求从降级响应恢复为正常转发响应。

## 五、指标校验

1. 访问 `curl -sS http://127.0.0.1:8080/metrics`。
2. 检查字段：
   - `circuit_state`
   - `circuit_open_total`
   - `circuit_half_open_total`
   - `circuit_closed_total`
   - `circuit_degraded_total`

## 六、测试命令

```bash
cd go_backend
go test ./...
go build ./...
go vet ./...
```

以上全部通过，且故障注入与恢复链路符合预期，可判定第四阶段完成。
