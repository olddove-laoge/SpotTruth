# 网关层设计总览

更新时间：2026-04-09

## 1. 网关层的作用

1. 统一入口：对外仅暴露一个稳定入口，隐藏上游服务细节。
2. 统一治理：把鉴权、限流、熔断、观测放在同一层做策略收口。
3. 统一追踪：请求级 `X-Request-ID` 打通日志、错误响应、指标分析。
4. 统一演示：通过 `/metrics` 直接接 Prometheus/Grafana，便于答辩与录屏。

## 2. 为什么这样设计

1. 低侵入：上游 Python 业务不必先重写，先由网关接管稳定性能力。
2. 可扩展：中间件链可按阶段增量演进，避免一次性大改。
3. 可验证：每层能力都可独立单测和回归，风险可控。
4. 可迁移：后续逐步把热点能力迁到 Go Handler 时，入口与治理策略不变。

## 3. 设计带来的好处

1. 故障隔离更强：限流与熔断让上游异常不会快速扩散。
2. 定位速度更快：request_id + 指标快照 + Prometheus 文本指标形成闭环。
3. 演示效果更好：可视化面板可直接展示 QPS、状态码比例、降级次数。
4. 运维成本更低：配置项环境变量化，联调与部署可复用同一套参数。

## 4. 核心思路（中间件责任链）

1. 请求进入网关后先分配/透传 `X-Request-ID`。
2. 记录结构化日志，保证每条日志可追踪。
3. 执行分桶限流和并发限流，提前拒绝超额流量。
4. 执行熔断策略，避免把坏流量继续压给上游。
5. 通过反向代理转发到上游，并采集指标。
6. 统一输出健康、就绪、指标与降级响应。

## 5. 核心代码索引

1. 网关入口与路由组装：`go_backend/internal/gateway/server.go`
2. 反向代理实现：`go_backend/internal/gateway/proxy.go`
3. request_id 中间件：`go_backend/internal/middleware/request_id.go`
4. 分桶限流：`go_backend/internal/middleware/bucket_limiter.go`
5. 并发限流：`go_backend/internal/middleware/concurrency_limiter.go`
6. 熔断降级：`go_backend/internal/middleware/circuit_breaker.go`
7. 指标采集与导出：`go_backend/internal/observability/metrics.go`
8. 配置加载：`go_backend/internal/config/config.go`

## 6. 核心配置项（示例）

1. 网关与上游：`GATEWAY_ADDR`、`UPSTREAM_BASE_URL`、`UPSTREAM_HEALTH_PATH`
2. 鉴权：`AUTH_ENABLED`、`AUTH_SIGNING_KEY`、`AUTH_ACCESS_TTL`
3. 限流：`MAX_IN_FLIGHT`、`BUCKET_LIMIT_*`
4. 熔断：`CB_*`
5. 超时：`READ_TIMEOUT`、`WRITE_TIMEOUT`、`RESPONSE_HEADER_TIMEOUT`

## 7. 指标与可视化

1. `/metrics`：Prometheus 标准文本格式。
2. `/metrics/json`：联调兼容端点。
3. 推荐看板指标：
   - `spottruth_requests_total`
   - `spottruth_in_flight_requests`
   - `spottruth_http_status_total`
   - `spottruth_limiter_rejected_total`
   - `spottruth_circuit_degraded_total`
   - `spottruth_circuit_state_value`

## 8. 第六阶段收口说明

1. 联调主链路中的 Python 工具调用已统一经网关转发。
2. 联调结果透出 `request_id`，可与网关日志和指标对齐。
3. 网关层可判定为阶段性完成，后续进入治理深挖阶段。
