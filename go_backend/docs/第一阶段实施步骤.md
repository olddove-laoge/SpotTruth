# SpotTruth Go 网关第一阶段实施步骤（D1-D3）

更新时间：2026-04-01
目标范围：P0-1（代理层关键超时）+ P0-2（服务端超时保护）

## 一、实施目标

1. 补齐代理层关键超时，避免上游抖动导致连接长时间挂起。
2. 补齐网关服务端读写与空闲超时，防止慢请求拖垮服务。
3. 配套单元测试，确保超时配置具备默认值、环境变量覆盖、非法值回退能力。

## 二、详细步骤（已按序执行）

### 步骤 1：补齐配置模型（已完成）

修改文件：
- internal/config/config.go
- .env.example

新增配置项：
- 服务端超时：
  - READ_TIMEOUT（默认 30s）
  - WRITE_TIMEOUT（默认 30s）
  - SERVER_IDLE_TIMEOUT（默认 60s）
- 代理层超时：
  - DIAL_TIMEOUT（默认 3s）
  - TLS_HANDSHAKE_TIMEOUT（默认 5s）
  - EXPECT_CONTINUE_TIMEOUT（默认 1s）

验收点：
- 支持环境变量覆盖。
- 非法值自动回退到默认值。

### 步骤 2：接入代理层超时（已完成）

修改文件：
- internal/gateway/proxy.go

具体动作：
1. 在 ProxyOptions 中增加拨号、TLS 握手、Expect-Continue 超时字段。
2. 抽取 newTransport 函数统一构造 http.Transport。
3. 在 Transport 中设置：
   - DialContext（含拨号超时）
   - TLSHandshakeTimeout
   - ExpectContinueTimeout
   - ResponseHeaderTimeout

验收点：
- NewReverseProxy 构造出的 transport 包含上述超时配置。

### 步骤 3：接入服务端超时（已完成）

修改文件：
- cmd/api-gateway/main.go

具体动作：
1. 将新增的代理超时配置传入 NewReverseProxy。
2. 在 http.Server 中补充：
   - ReadTimeout
   - WriteTimeout
   - IdleTimeout

验收点：
- 启动时即启用服务端读写与空闲连接保护。

### 步骤 4：补充测试（已完成）

修改文件：
- internal/config/config_test.go
- internal/gateway/proxy_test.go

新增/增强测试点：
1. config 测试：
   - 新增字段默认值校验。
   - 环境变量覆盖校验。
   - 非法值回退校验。
2. proxy 测试：
   - 校验 transport 的超时字段映射。
   - 校验 DialContext 已设置。

### 步骤 5：执行验证（已完成）

执行命令：
- go test ./...

通过标准：
- 所有测试通过。
- 构建成功，无编译错误。

## 三、联调后应出现的结果

第一阶段不改变业务路由语义，联调外观行为应保持兼容，仅增强异常场景保护能力。

### 1）健康检查

请求：
- GET /healthz

预期：
- HTTP 200
- JSON 包含：
  - status: ok
  - service: spottruth-api-gateway

### 2）正常代理请求

请求：
- 任意业务路由（网关转发到 Flask）

预期：
- 正常返回上游响应。
- 日志保留 method/path/status/duration。

### 3）上游慢响应场景

场景：
- Flask 响应头返回明显超时。

预期：
- 网关在 RESPONSE_HEADER_TIMEOUT 到达后失败返回（bad gateway）。
- 不会无限期阻塞连接。

### 4）慢连接/慢请求场景

场景：
- 客户端长时间不发送完整请求体或写入非常慢。

预期：
- 触发 ReadTimeout/WriteTimeout/IdleTimeout，连接被回收。
- 网关整体吞吐不被单个慢连接持续占用。
