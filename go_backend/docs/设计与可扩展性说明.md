# SpotTruth 项目 Go 后端设计与可扩展性说明

## 一、引入 Go 的场景与边界

1. 高并发 API 网关：
   - 作为所有外部请求的统一入口，负责路由、限流、认证、日志、健康检查。
   - 反向代理到现有 Python/Flask 服务，后续可平滑切换部分接口到 Go 实现。
2. 任务调度与异步处理：
   - 对于高并发、IO 密集型或需异步处理的任务（如大批量评论分析、数据抓取），可用 Go 实现任务分发、队列、并发 worker。
3. 领域服务拆分：
   - 随业务增长，将部分高频/高性能需求的 API 拆分为独立 Go 微服务（如用户鉴权、数据聚合、实时统计等）。
4. 工程化与可维护性提升：
   - 利用 Go 的静态类型、部署便捷、跨平台特性，提升后端整体工程质量。

## 二、API 网关设计

- 统一入口，监听 8080 端口。
- 健康检查接口 `/healthz`，便于监控与自动化运维。
- 反向代理所有业务流量到 Flask（127.0.0.1:5000），后续可逐步迁移部分路由到 Go 内部 handler。
- 支持中间件扩展（日志、限流、认证等）。
- 配置全部支持环境变量，便于多环境部署。

### 2.1 已落地能力（当前版本）

1. 高并发连接池：
   - `MAX_IDLE_CONNS`
   - `MAX_IDLE_CONNS_PER_HOST`
   - `IDLE_CONN_TIMEOUT`
   - `RESPONSE_HEADER_TIMEOUT`
2. 并发保护：
   - `MAX_IN_FLIGHT` 控制在途请求上限。
   - 达到上限后快速返回 `503 Service Unavailable`，保护下游 Flask 服务。
3. 可观测性：
   - 请求日志记录 `method/path/status/duration/remote`。
4. 生命周期管理：
   - 支持 `SIGINT/SIGTERM` 优雅停机。
5. 鉴权组件（库级能力）：
   - 已实现 JWT Token 生成/解析与角色鉴权中间件（`internal/auth`）。
   - 当前尚未接入网关主处理链路，属于“代码已就绪、路由未启用”。

## 三、与现有 Python 服务协作

- 保持接口兼容，前端/调用方无感知切换。
- 通过 HTTP/REST 协议通信，必要时可用 gRPC/消息队列做异步解耦。
- 逐步将高并发、性能瓶颈接口迁移到 Go，低频/复杂业务仍由 Python 处理。

## 六、后续可扩展方向

1. 增加 JWT/Session 认证中间件。
2. 接入分布式任务队列（如 NSQ、RabbitMQ）。
3. 监控与链路追踪（Prometheus、Jaeger）。
4. 逐步将高并发、性能敏感接口迁移到 Go。
5. 支持多语言/多平台部署。

## 八、网关方案表与后续计划（更新于 2026-04-01）

### 8.1 方案表（现状 + 风险 + 计划）

| 模块 | 当前实现 | 状态 | 主要风险 | 下一步动作 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 反向代理主链路 | 已支持所有业务路由转发，含连接池与基础错误处理 | 已落地 | 代理层超时维度不全（未显式配置拨号/握手/100-continue 超时） | 补齐 `http.Transport` 关键超时并增加慢上游单测 | P0 |
| 网关服务超时保护 | 仅配置 `ReadHeaderTimeout` 与优雅停机超时 | 部分落地 | 慢请求体/慢写回场景下保护不足 | 增加 `ReadTimeout`、`WriteTimeout`、`IdleTimeout` 配置与默认值 | P0 |
| 并发保护 | `MAX_IN_FLIGHT` 在途请求限制 + 503 快速失败 | 已落地 | 返回语义较弱，缺少重试提示和命中指标 | 增加 `Retry-After` 与结构化错误体，补充命中统计 | P1 |
| 健康检查 | `GET /healthz` 存活探针 | 已落地 | 上游异常时仍可能返回健康 | 新增 `GET /readyz` 上游轻量探测 | P1 |
| 鉴权能力 | JWT TokenManager、AuthMiddleware、RequireRole 已实现并有单测 | 代码就绪 | 未接入主链路，当前代理入口默认放行 | 在网关 handler 中引入白名单路由 + 鉴权链，补充端到端用例 | P0 |
| 可观测性 | 请求日志覆盖 method/path/status/duration/remote | 已落地 | 缺少请求 ID 透传与分级日志字段 | 增加 request_id、upstream_status、error_code 字段 | P2 |
| 测试覆盖 | config/gateway/auth/middleware 单测已覆盖关键路径 | 已落地 | 缺少超时、readiness、鉴权接入后的集成回归测试 | 补齐失败路径与集成测试矩阵 | P1 |

1. 第一阶段（D1-D3，稳定性优先）
