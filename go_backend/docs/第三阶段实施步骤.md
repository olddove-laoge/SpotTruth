# SpotTruth Go 网关第三阶段实施步骤（D8-D14）

更新时间：2026-04-07
目标范围：P1（`/readyz`、限流语义增强、关键指标补齐）+ 联调固化

## 一、步骤进程

1. 步骤 1：定义健康探针分层（先完成）
   - 保留 `/healthz` 作为存活探针（liveness）。
   - 新增 `/readyz` 作为就绪探针（readiness），主动探测上游可用性。

2. 步骤 2：增强限流返回语义（再完成）
   - 并发超限时返回结构化 JSON 错误体。
   - 增加 `Retry-After` 响应头，给调用方明确重试指引。

3. 步骤 3：补齐关键运行指标（再完成）
   - 增加网关内置指标聚合器（轻量实现，不引入额外外部依赖）。
   - 暴露 `/metrics` 接口，输出核心指标快照。

4. 步骤 4：接入配置与主程序（再完成）
   - 通过环境变量控制 readiness 超时、上游探测路径、限流重试提示秒数。
   - 在网关启动时组装 readiness 检查器并注入 handler。

5. 步骤 5：测试与联调固化（最后完成）
   - 补充/更新单测覆盖 readiness 成功/失败、限流语义增强。
   - 在 README 测试章节补充标准联调链路步骤。

## 二、验收标准

1. `/readyz` 在上游正常时返回 200，异常时返回 503 且包含原因。
2. 并发超限返回 503 JSON，并带 `Retry-After`。
3. `/metrics` 能输出请求总量、在途请求、状态码分布、限流命中、延迟统计。
4. 联调链路 `gateway health -> python tool -> integration test` 可重复执行。
5. `go test ./...`、`go build ./...`、`go vet ./...` 全部通过。

## 三、实施结果（2026-04-07）

1. 健康探针分层已落地
   - 新增 `GET /readyz`，通过上游健康接口执行主动探测。
   - `GET /healthz` 继续保留为 liveness，二者语义清晰分离。

2. 限流语义已增强
   - 并发超限返回统一 JSON 错误体。
   - 增加 `Retry-After` 响应头，调用方可按秒级重试。

3. 关键指标已补齐
   - 新增网关内置轻量指标聚合器。
   - `GET /metrics` 提供请求总量、在途请求、状态码分布、限流命中、平均时延与 goroutine 数量。

4. 联调步骤已固化到 README
   - 已在 README 的“测试与联调”章节补充固定回归链路与命令示例。

5. 回归验证结果
   - `go test ./...` 通过。
