# 第六阶段实施步骤（Agent 穿网关链路收口）

更新时间：2026-04-09

## 一、阶段目标

1. 将联调主链路中的 Agent/Python 工具调用统一收敛到 Go 网关入口。
2. 避免联调时出现“同一功能既可走网关又可本地直调”的旁路分叉。
3. 保证每次联调请求具备 request_id，可在日志和指标中稳定追踪。

## 二、本阶段完成项

1. 联调入口统一为“直连网关”：
   - 调用方先通过 `POST /api/v1/auth/login` 获取 token。
   - 后续业务请求统一调用 `网关/api/classify`。
2. 上游服务补齐分类端点：
   - 新增 `POST /api/classify`（供网关反向代理到上游时使用）。
3. 请求追踪闭环：
   - 联调调用携带 `X-Request-ID`。
   - 返回体透出网关响应头中的 `request_id`，便于排障。

## 三、关键实现位置

1. `go_backend/internal/gateway/server.go`
   - 登录签发路由与鉴权白名单。
2. `go_backend/internal/gateway/auth_handler.go`
   - 最小登录签发接口（`POST /api/v1/auth/login`）。
3. `new_idea/agent_api.py`
   - 上游业务接口（`/api/classify`）。

## 四、验收标准

1. `POST /api/v1/auth/login` 返回 200 且可获取 `access_token`。
2. 带 Bearer 调用 `POST /api/classify` 返回 200，且包含分类结果。
3. 网关不可用或上游异常时，返回可读错误信息并可通过 `request_id` 追踪。

## 五、如何快速验证

1. 启动上游服务（5000）和 Go 网关（8080）。
2. 调用：

```bash
TOKEN=$(curl -sS -X POST "http://127.0.0.1:8080/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"account":"spottruth_user","password":"spottruth_user_123","login_type":"password"}' | jq -r '.data.access_token')

curl -sS -X POST "http://127.0.0.1:8080/api/classify" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "X-Request-ID: phase6-demo-1" \
  -d '{"product_name":"苹果手机"}'
```

3. 观察返回 JSON：
   - `category` 有值
   - 网关日志可按 `request_id` 追踪

## 六、阶段结论

1. 第六阶段“Agent 穿网关链路收口”已完成（以联调主链路为验收边界）。
2. 网关层阶段性建设完成，可进入后续治理深挖（鉴权自动化、按路由策略模板、能力内聚）。
