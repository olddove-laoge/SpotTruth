# 第六阶段实施步骤（Agent 穿网关链路收口）

更新时间：2026-04-09

## 一、阶段目标

1. 将联调主链路中的 Agent/Python 工具调用统一收敛到 Go 网关入口。
2. 避免联调时出现“同一功能既可走网关又可本地直调”的旁路分叉。
3. 保证每次联调请求具备 request_id，可在日志和指标中稳定追踪。

## 二、本阶段完成项

1. `web_app` 联调接口改造为穿网关：
   - `POST /api/python/tool-test`：由本地分类改为调用 `网关/api/classify`。
   - `POST /api/integration/test`：健康检查成功后，继续通过网关调用 `api/classify`。
2. 上游服务补齐分类端点：
   - 新增 `POST /api/classify`（供网关反向代理到上游时使用）。
3. 请求追踪闭环：
   - 联调调用携带 `X-Request-ID`。
   - 返回体透出网关响应头中的 `request_id`，便于排障。

## 三、关键实现位置

1. `web_app/app.py`
   - `build_gateway_request_headers`
   - `/api/python/tool-test`
   - `/api/integration/test`
   - `/api/classify`
2. `web_app/test_app_api.py`
   - 补充和更新网关转发链路测试、request_id 断言。

## 四、验收标准

1. `POST /api/python/tool-test` 在网关可用时返回 200，且包含 `request_id`。
2. `POST /api/integration/test` 同时验证：
   - 网关健康探针通过；
   - 工具调用走网关成功并返回分类结果。
3. 网关不可用时，联调接口返回 502，并给出可读错误信息。

## 五、如何快速验证

1. 启动上游服务（5000）和 Go 网关（8080）。
2. 调用：

```bash
curl -sS -X POST "http://127.0.0.1:5001/api/python/tool-test" \
  -H "Content-Type: application/json" \
  -d '{"gateway_url":"http://127.0.0.1:8080","product_name":"苹果手机"}'
```

3. 观察返回 JSON：
   - `ok=true`
   - `category` 有值
   - `request_id` 非空

## 六、阶段结论

1. 第六阶段“Agent 穿网关链路收口”已完成（以联调主链路为验收边界）。
2. 网关层阶段性建设完成，可进入后续治理深挖（鉴权自动化、按路由策略模板、能力内聚）。
